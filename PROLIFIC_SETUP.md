# Prolific launch checklist — Moral Case Relevance

The participant-facing study is live on GitHub Pages:
https://i-kiran.github.io/precedent-study/

## Study design and data

- One fixed target situation and **eight prior dilemmas**, presented in a random order.
- **Required:** one 1–7 relevance judgment for each dilemma.
- **Optional:** confidence slider from 0 to 100 and a short written explanation for each judgment.
- The participant interface does **not** reveal moral-value labels, near/far, deep/shallow, dataset IDs, or case-selection rationale.
- Each participant gets a random response UUID. Data also contains Prolific participant ID, study ID, and session ID; timestamps; each case's dataset ID, experimental conditions, display order, relevance score, optional confidence and explanation, and response time.

## Before recruiting participants

**Do not launch until the following are completed:**

1. Review consent language, participant-facing instructions, and any institution-specific research ethics / IRB requirements.
2. Create a **private** GitHub repository for responses (distinct from the public study repository).
3. Deploy the server-side receiver in \`api/submit.js\` to a service that supports HTTPS POST handlers, such as Vercel.
4. Set secrets server-side: \`GITHUB_RESULTS_TOKEN\` (fine-grained token scoped only to the private responses repo, Contents read/write), \`GITHUB_RESULTS_REPO\` (e.g. \`owner/private-repo\`), and optionally \`GITHUB_RESULTS_BRANCH=main\`. Never commit the token or expose it in page JavaScript.
5. In \`index.html\`, set \`RESULTS_ENDPOINT\` to the real HTTPS URL of \`/api/submit\`.
6. In Prolific's study creation form, choose a **study link** and pass identifiers via URL parameters. The study code reads the standard \`PROLIFIC_PID\`, \`STUDY_ID\`, and \`SESSION_ID\` values.
7. Copy the **actual Completion URL** generated by Prolific for this study. In \`index.html\`, set \`PROLIFIC_COMPLETION_URL\` to that exact URL. Do not invent a completion code. For safety, the participant study remains in *preview mode* until **both** endpoint and completion URL are present.
8. Run at least one pilot from Prolific's preview using URL parameters. Check that the private repo contains an individual CSV at \`responses/<UUID>.csv\`, including the three Prolific IDs, randomized order, all eight ratings, optional confidences, and response times. Verify a participant can only return to Prolific **after the receiver confirms a save**.
9. Before recruiting broadly, configure rate limiting, abuse protection, and monitoring for the receiver. Checking request Origin is not authentication or protection against script-based abuse. Confirm response access and retention policy.

## Participant flow

1. Welcome and consent.
2. Read the target situation (no condition labels).
3. Eight case comparisons in randomized order, each with:
   - target and prior scenario,
   - **required** 1–7 relevance scale,
   - **optional** 0–100 confidence slider (blank unless moved; clearable),
   - **optional** free-text reasoning field.
4. Final screen: HTTPS submission, confirmation of server save, then a button to return to Prolific via the real Completion URL.

The study keeps progress in **sessionStorage** under a key that includes the Prolific Session ID when present. It does not submit incomplete data to the backend. Responses are not available to the researcher until the storage endpoint is configured.

## Important note

This is a working participant interface, **not yet a launch-ready study**. Until completion and private data storage have been configured, the page intentionally displays a preview warning and a local CSV backup option.
